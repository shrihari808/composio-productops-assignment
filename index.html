Headline finding

Half of the 100 requested apps are ready to build today, 89 vendors ship official MCP servers, and 35 sit behind production review, admin or partner gates that raw LLM research misses.

Six patterns across 100 apps. Dual auth and vendor MCPs now lead.

Clustered from 432 live documentation links and 1,842 production Composio toolkit schemas.

Pattern 1 · Auth landscape

88 OAuth2

Dual-auth (OAuth2 + API Key/Bearer) is standard

OAuth2 appears in 88/100 apps, followed by API Key (64) and Bearer Token (62). 86/100 apps expose two or more auth schemes, so supporting both managed OAuth and static key fallback unlocks the widest coverage.

Pattern 2 · Self-serve wins

50 ready

Dev/Infra and Productivity stay nearly 100% open

Productivity and Project Management and Communications and Messaging deliver the highest density of Ready Today builds, pairing free developer sandboxes, clean OpenAPI/GraphQL specs and instant token provisioning.

Pattern 3 · Hidden gate trap

35 gated

Self-serve portal does not equal production access

35/100 apps require app review, paying customer admin accounts or partner contracts—concentrated in Finance and Fintech and Ecommerce (Google Ads, Meta Ads, LinkedIn Ads, WhatsApp Business and Amazon SP-API).

Pattern 4 · MCP inflection

89 official

89/100 vendors ship official MCP servers

Led by CRM and Sales and Support and Helpdesk, reaching enterprise tools like DealCloud and Otter AI. Several vendors (e.g., Otter AI) gate full REST APIs behind Enterprise while exposing narrower self-serve OAuth MCP endpoints.

Pattern 5 · Non-API edge cases

2 CLIs

2 tools are local CLI binaries, not cloud APIs

Sherlock and Mermaid CLI ship no hosted REST API, while YouTube Transcript is a scraper wrapper. Turning them into agent tools requires wrapping a hosted runner (Apify / Mermaid Chart MCP) or a sandboxed workbench.

Pattern 6 · Trigger headroom

57 vs 23

Webhooks outpace live Composio event triggers

57 vendors document webhooks, yet only 23 matched Composio toolkits ship triggers. 27 existing Composio toolkits support vendor webhooks today with 0 triggers—a direct retention win.

90%+ automated

Where the agent excelled

  • Massive parallel primary-source retrieval: Researched all 100 apps across 200+ Exa semantic queries and verified 432 live doc URLs in minutes rather than days.
  • Catching 2025-2026 official MCP launches: Found newly launched official remote MCP servers (HubSpot, DealCloud, WhatsApp Business, Otter AI, Linear, Stripe, Plaid) that static LLM memory misses.
  • Programmatic Composio catalog auditing: Scanned 1,842 live Composio toolkits via /api/v3.1/toolkits to compute exact tool counts, trigger counts and auth mode cross-checks with zero manual scraping.
  • Repo and CLI forensics: Used Composio deepwiki_mcp and github toolkits to verify whether GitHub MCP repos belong to official vendor orgs versus community forks.

Real failure modes caught

Where a human was essential

  • Bot-shielded doc portals (caught in 5-app pilot): Meta (developers.facebook.com), LinkedIn and Cloudflare return HTTP 400/403/timeouts to headless clients. Our initial link checker mistakenly dropped valid WhatsApp URLs and swapped in a ?locale=zh_CN page—requiring a human fix combining HTTP checks with Exa /contents status codes.
  • Free dev portal vs. production app review: Pass 1 occasionally labeled Ads and Fintech apps as Self-Serve Free because sandbox signup is free, missing mandatory business verification or developer token review for production.
  • Split-surface products: Products like Otter AI (Enterprise-only REST API vs. self-serve 3-tool OAuth MCP) and NotebookLM (consumer web app vs. GCP Enterprise API) required human judgment on the buildability rubric.
  • Catalog alias disambiguation and obscure portals: Human and browser review caught false catalog matches (linkedin vs. linkedin_ads; Amazon shopping vs. SP-API), entity confusion (Paygent Connect vs. Payman AI), Clay's 404 HTTP API docs, and FanBasis's rebrand to Commas.
